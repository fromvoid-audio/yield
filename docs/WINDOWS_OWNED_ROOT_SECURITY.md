# Windows owned-root security snapshot

`ProductionRootCapability::validate` checks the exact retained profile or profile-child directory before original FileOperationOwner registration and at existing root revalidation boundaries. External Source roots retain their separate authority contract. The helper receives only the original directory File; it never looks up security metadata by path and does not set an ACL.

The snapshot requires a disk-type, non-reparse, non-device directory with nonzero original identity before and after querying OWNER and DACL. Because the original production handle has attribute access only, a read-only ReOpenFile obtains READ_CONTROL plus FILE_READ_ATTRIBUTES on that exact object, retaining the original delete-sharing barrier and verifying both identities before and after the query. Disk type does not establish local storage or filesystem qualification. The owner must equal the current process TokenUser SID. A fixed, aligned 512-byte TokenUser buffer and 16-KiB security descriptor buffer reject larger replies. Pointer arithmetic, complete SID bodies, self-relative descriptor offsets, ACL sizes and at most 64 ACEs are checked before interpretation.

The accepted conservative grammar uses revision-1 SIDs, revision-2/4 ACLs, ordinary allow/deny ACEs, the five documented inheritance flags, and SDK-checked directory access/control masks. An applicable foreign-SID allow containing ADD_FILE, ADD_SUBDIRECTORY, WRITE_EA, DELETE_CHILD, WRITE_ATTRIBUTES, DELETE, WRITE_DAC, WRITE_OWNER, GENERIC_WRITE or GENERIC_ALL refuses. SYSTEM and Administrators receive no exemption. Read/execute and synchronization grants are permitted. Inherit-only ACEs do not apply to the current directory; a deny never cancels a foreign allow for this conservative decision. Unknown shapes, rights, controls, malformed spans and null DACLs refuse. An empty DACL is valid but gives no new authority.

Consequently default Windows directories may refuse. This is intentional observation policy, not permission repair. A descriptor snapshot cannot establish secure ancestors, canonical OS per-user bootstrap, persistent volume UUID, immutable ACL lifetime, exclusion of existing writable handles or mappings, created-stage provenance, permits or namespace admission. Those contracts remain open under OPT-2218; OPT-2363 retains its original scoped limits.

## Bounded scratch and original backing

The one fixed `SnapshotBuffers` heap allocation contains 16,384 security bytes and 512 token bytes, aligned to 16 bytes. Its exact `size_of` is asserted to be 16,896 bytes, including alignment/padding. `Box::new_uninit` allocates that known size; in-place byte initialization establishes both arrays before any reference or native API use, avoiding a descriptor-sized stack temporary. No native length hint controls allocation. No descriptor-sized diagnostic string is retained.

OPT-2398 supplies original root construction and retained metadata backing. This leaf adds the exact 16,896-byte allocation cost to original profile construction prepayment and preserves it when binding/shrinking the original capability input. Source roots neither pay nor query this profile policy. All production capability validation occurs serially on the single original FileOwner worker: registration, `validate_for_owner`, staged validation before/after hashing, and publication preparation/revalidation. One scratch allocation per capability is active at a time, even when several root roles are validated sequentially. The Box and native token/reopened handles drop before original root credit. Each owning FileOwner funds its own capabilities; shared observations create no allocation grant.

`ProductionRootCapability` is not cloned and exposes no Arc/Weak handle. Registration retains it inline in the original registry. Publication `BindingData` aliases retain staging observations and privately funded `RootLiveness`, not that capability; their possible off-worker staging revalidation does not query a directory SD. Retirement and worker teardown remove the capability and close liveness, preventing another original registry-based SD query. Its allocation debit may then return after scratch destruction; the separate liveness allocation debit remains until its actual last alias drops. No SID or descriptor slice escapes the helper.

Existing callback/thread stack accounting excludes the fixed parser references/scalars, identity values, TOKEN_USER and BY_HANDLE_FILE_INFORMATION ABI records, and Box/handle controls; none scale with native descriptor hints or ACE count. Kernel token/descriptor and native allocator/error storage retain the existing platform-accounting limitation. Canonical checks and GNU compilation do not qualify those external native allocations. Final integration must rebase onto the actual verified OPT-2398 merge and verify both prepayment and retained charge; the snapshot cannot create or refund funding.

## Verification

Portable tests exercise every mutation/read bit, SYSTEM/Administrators parity, exact owner equality, inherit-only and deny behavior, unknown rights/ACE/control grammar, all truncations, finite limits and checked token pointers. The Windows conditional harness uses externally prepared private, foreign-mutable and foreign-owned directories, plus genuine original Owner registration/revalidation and refusal. No harness sets ACLs.

Native qualification requires the linked Windows verification issue OPT-2410: current unelevated token, local NTFS/MSVC, exact fixture owner/DACL evidence and actual test exits. Positive descendants require externally prepared inheritable owner-only ACLs; TEMP/TMP must also point to a private inheritable parent for existing native positive suites. Cross-compilation does not supply native execution evidence.

## Native API references

Microsoft's [ReOpenFile documentation](https://github.com/MicrosoftDocs/sdk-api/blob/docs/sdk-api-src/content/winbase/nf-winbase-reopenfile.md) explicitly supports directory BACKUP_SEMANTICS and OPEN_REPARSE_POINT, requires compatibility with still-open access/share modes, and forbids FILE_ATTRIBUTE flags (reviewed file blob `4a9ad887af165036073b8a9b272d2933b3697b32`). [GetKernelObjectSecurity](https://github.com/MicrosoftDocs/sdk-api/blob/docs/sdk-api-src/content/securitybaseapi/nf-securitybaseapi-getkernelobjectsecurity.md) requires READ_CONTROL for OWNER/DACL and returns a self-relative descriptor (reviewed blob `c6eb8f19c24cb6873766a939d2c18d6a1e702e1c`). The original production OpenOptions binding uses CreateFile, satisfying ReOpenFile's original-handle contract. The helper changes neither ACLs nor privileges; backup/restore privilege bypass is outside snapshot qualification.

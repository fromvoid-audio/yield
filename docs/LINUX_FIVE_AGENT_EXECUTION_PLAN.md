portable prerequisites before consumers. A Linux: Blocked label asks an agent to
inspect a dependency; it does not mean a Mac is needed. Missing design, public

A planning timebox means split the scope and continue, not abandon the objective.

## How to resolve a blocked issue

1. Read the full issue, live blocking relations, full prerequisite descriptions
   and latest comments. Follow prerequisites to the first unresolved leaf. Read
   current source and merged evidence; older appended audits can be stale.
2. Remove a completed/obsolete blocking link only after verifying its actual
   disposition and source. Preserve traceability and any requirement not fulfilled
   by that disposition. Never infer that a Done decision supplies its implementation.
3. Claim an unclaimed portable prerequisite and implement it first. For a missing
   contract, choose the exact existing owner/caller, bounded input/result, stable
   identity, ordering, rejection and recovery semantics; document and test that
   decision, then implement its consumer. A model cannot mint live authority.
4. Split a whole-parent, circular or overbroad requirement into the exact portable
   leaf and separate platform acceptance. Add actual blocking links and acceptance
   commands. Do not move an independently executable inventory/guard behind all
   the implementations it is meant to enumerate or constrain.
5. After a verified merge, refresh directly affected consumers and their readiness.
   Promote only their executable scope. Preserve tracking parents until all original
   acceptance is met. Choose the next prerequisite or consumer and continue.

A safe ownership contract remains necessary. Resolve its portable design or
implementation instead of waiving it as a native test. If an accepted effect contract
cannot be satisfied by a primitive here, state that precise external requirement.
The current publication/cleanup workers' Unsupported result is retained evidence,
not successful mutation. Windows primitive availability is not workflow qualification;
macOS pathname operations do not establish held-object provenance under the accepted
namespace-substitution policy. Platform qualification issues remain open.

## Claim, merge and verification protocol

- Mark In Progress; comment with chat, branch, worktree and intended files. Recheck
  for competing claims before editing. Linear is not an atomic claim lock: if two
  claims appear, yield or agree distinct scopes. Elapsed time does not revoke a claim.
- Use an isolated worktree/branch from current origin/main. Honor repository/AGENTS
  instructions. Claim shared GPUI action register, yield-session/src/lib.rs, global
  owner/schema, source DB/curation and guard-script edits explicitly. Avoid holding
  unrelated file ownership; update claims when scope changes.
- Implement the stated acceptance through existing owners. Run relevant real tests,
  locked application checks and repository guards. Contract/model evidence must be
  labeled and cannot count as production physical qualification.
- Rebase after other merges and rerun affected checks. PR creation, merging and Linear
  updates are authorized. Merge the tested head, verify the merge tree matches it,
  record PR/head/merge, exact commands, results and limits; then mark the leaf Done.
- Put unavailable native verification in a scoped platform issue with exact commands,
  fixture/setup and expected result. Keep missing implementation open and keep parents
  open. Separate implementation, source-model evidence and physical acceptance.

## When to move on or stop

A necessary unavailable native macOS/Windows runtime, physical device/volume, signing
credential/account, external permission or deployment resource can block that step.
Record the specific resource, the failed/missing step, source evidence and exact
platform/external unblock issue; proceed with another portable slice or issue.
A missing design, implementation or Linux test is not such a blocker.

Before stopping, recheck the whole live Linux queue and reachable prerequisites,
including newly created leaves. Only stop when work is complete or every remaining
unclaimed scope genuinely needs a resource this environment cannot provide. If all
remaining portable work is claimed by other agents, coordinate and wait/recheck
rather than duplicate it or report it as a platform blocker. A single blocked or
claimed issue, tracking parent, old timebox or empty Ready filter is insufficient.

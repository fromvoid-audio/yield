# Recording restart producer backing

The optional-input complete recording restart reader prepays the original
retained-row totals, eight-key operation and slot pages, sequence audit and
captured-byte decoding on the same input pool. Original row/byte ceilings and
whole-page scalar conversion order remain intact. Valid UUID TEXT is borrowed;
UTF-8 and driver errors preserve their original precedence over UUID errors.

Each operation uses the existing funded complete record visitor and reservation
control verification. Captured chunks preserve the original two-query scalar and
payload boundary, including independently bounded payload rechecks. They borrow
the SQLite BLOB and run the unchanged closed streaming decoder: historical
noncanonical JSON remains accepted and no Value tree or replacement canonical
chunk gate is introduced. Both readers share the original scalar PCM/header
prefix classifier.

Working/path/error storage, geometric page capacity, actual decoded strings and
byte arrays, and original proposal validation/hash encoding are prepaid before
those producers. Decoded data precedes its credits in drop order. Selected
failures transfer working/page/decoder/native loans into the original input
carrier, preserving already retained nested loans after the caller is dropped.

Owned SQLite tests cover dense PCM, historical byte compatibility, no owned
record or BLOB copy, page UTF-8 precedence, original prefix and duplicate-sequence
errors, payload mutation between the two queries, selected-error lifetime and
pressure refusal before page or byte growth. The existing System historical
allocation regression does not measure these new producers; GNU Windows
compilation is not native positive capacity qualification.

Transaction settlement, post-intent provider growth and the complete Legacy
admission worker remain separate work under OPT-2373. Historical rows supply no
live capacity, execution, custody or settlement authority.

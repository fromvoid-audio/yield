# GPUI browser accessibility adapter

The Yield browser attaches one `AxRegistry` to its real macOS GPUI window. The registry follows the browser entity's lifetime. AX callbacks enqueue bounded events; the browser rechecks current identities and dispatches them on its GPUI window context.

The adapter exposes Search, Add source, visible source rows and their Forget buttons, visible folder rows and their expand buttons, Folder scope, Refresh source, and visible sample rows. It also exposes the displayed sort headers, random navigation and sample name view controls, collection, playback type and rating filters, and the tag filter toggle and editable field. Names, selection, counts, scope, errors, values, and enablement come from the same browser state as the drawn controls. GPUI `uniform_list` supplies the actual visible row ranges; prepaint canvases supply each control's actual frame. Hidden sort columns are omitted, and filters without an active source are disabled. Unchanged AX snapshots are not reconciled again on every browser render.

## Native validation

On macOS 26.6.2, a debug `yield-gpui` build was launched with temporary sources. `AXUIElement` queries found `AXWindow` children with expected button and row roles, names, values, enabled state, and nonzero frames. Native AX focus succeeded for a source row. Native `AXPress` on Folder scope changed `Direct only` to `All descendants`; on a folder row it changed the selected folder and kept focus; on a folder toggle it changed `Collapsed` to `Expanded` and exposed the child row; on sample `b.wav` it changed selection from `a.wav` to `b.wav` and kept focus; on a temporary source's Forget button it removed both source AX children. With 80 sample files, the native AX tree contained 19 sample rows, matching GPUI's visible list range rather than the entire source. The temporary source scan reported a local session persistence warning, so these results validate UI and AX behavior only.

OPT-1875 adds the editable field contract. The native text-field fixture reports `AXValue` as settable and advertises no press action; AX value edits update GPUI-owned text. A separate button advertises and performs `AXPress`. In the real browser, setting Search to `b` through AX reduced the sample AX rows from `a.wav` and `b.wav` to `b.wav`. Search edits use the same `SearchChanged` projection path as keyboard edits.

For OPT-1749, an isolated `Yield OPT-1749` debug bundle was launched with two temporary WAV files and a temporary home directory. Direct `AXUIElement` queries found the new sort, view, and filter controls with their expected roles, names, values, enabled state, and nonzero frames. Native `AXPress` changed Rating sort from `Not sorted` to `Ascending`, random navigation from `Off` to `On`, sample name view from `Disk` to `Label`, and collection, playback type, rating, and tag filter toggles from `Off` to `On`. Native `AXValue` replacement changed the tag filter field to `kick`. After pressing Forget source, the collection, playback type, and rating filters reported disabled and advertised no actions. The temporary source scan reported a local session persistence warning, so these results validate UI and AX behavior only. Assistive-technology acceptance remains tracked separately by OPT-1759.

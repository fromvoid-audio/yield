# Original publication target preparation (OPT-2268)

The private file-owner producer accepts the original retained staging-validation reply,
not a cloned or decoded receipt. The original worker checks its receipt/tombstone,
actual registered production roots and profile/source boundary, direct absent target,
original no-follow regular staging descriptor, single link, length, content hash and
same-volume descriptor facts. Exact duplicates repeat those native and root checks;
changed publication identity or target conflicts. The readonly descriptor remains held.

A binding has its original deadline (at most two seconds), original root-registration
lifetime witnesses and original owner liveness. Root retirement or owner loss closes
scalar liveness; duplicates never renew a retained binding. Scalar liveness does not
revalidate current source registration, filesystem contents or native mutation rights.
Actual entry must repeat those checks under the complete journal-issued gate.

Preparation debits 64 KiB from the existing 4 MiB input pool through the final binding
alias. At most 32 live bindings exist. A 32 KiB registry debit covers its bounded weak
nodes and allocation headers until original worker shutdown. The complete request,
retained receipt dynamic capacities (limited to 16 KiB), bounded serialization image,
8 KiB streaming scratch, root witnesses and result transport fit the preparation debit.
Original 32-command control queue and 64-result credits remain in use. Expiry does not
refund live backing. Cancellation/lost reply releases only memory and handles; it does
not refund physical reservations, staging claims or genuine settlement obligations.

Linux tests exercise actual file-worker/profile/descriptor preparation, copy refusal,
acknowledged original receipt replay, same-inode changed content, inode replacement,
FIFO substitution, target collision, root replacement/retirement, owner loss, duplicate
expiry, binding/result/input saturation and cancellation. Preparation dispatches no
namespace effect. The macOS `genuine_registered_source_drain_closes_duplicate_preparation`
harness compiles on Linux and verifies the genuine unsupported production ownership/reserve
bootstrap refusal before registration. On macOS it uses actual source registration/drain/retirement;
it requires a native SDK/runtime and qualified protected-reserve filesystem. Its positive
runtime result is a separate native verification obligation, not a Linux contract fixture.

Windows observation opening is currently unsupported and refuses preparation. The
readonly handle and device facts do not qualify a mutation-capable held-object backend
or atomic no-replace effects. OPT-2218/2219 remain open. Full OPT-2215/2216 remain open
for genuine source/claim/capacity composition, journal lifetime slots and mutation entry,
completion, cancellation, shutdown and settlement. No journal schema or family effect
is changed by this preparation leaf.

The two-second deadline is checked between observations and streaming reads. It is
cooperative; it cannot interrupt a kernel filesystem call already in progress.

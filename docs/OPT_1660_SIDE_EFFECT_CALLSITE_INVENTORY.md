# OPT-1660 production side-effect inventory

Status: in progress for [OPT-1660](https://linear.app/boostnlvp/issue/OPT-1660). This inventory describes the `origin/main` checkout at `74b5ad1cc`. It names the current authority or an explicit exception; it does not migrate a caller or change product policy. An owner named in the target architecture is not evidence that the current caller is routed through it.

## Scope and review method

The review covers the Rust production crates under `crates/`: profile and source/global SQLite writes, journal and capacity persistence, filesystem mutation, cache/artifact publication, scanner/watch observations that can feed durable writes, and UI/recording effects. It excludes `#[cfg(test)]` modules, `tests.rs`, `*_tests.rs`, fixture modules, build scripts, and developer tools from production claims. Inline tests in otherwise production files must be excluded at their `#[cfg(test)] mod tests` boundary; a raw `rg` count alone includes fixtures. The source SQL and file ownership rules come from [SOURCE_WRITER_CONTRACT.md](SOURCE_WRITER_CONTRACT.md), [FILE_OPERATION_OWNER_CONTRACT.md](FILE_OPERATION_OWNER_CONTRACT.md), and the owner table in [IO_ARCHITECTURE_TARGET.md](IO_ARCHITECTURE_TARGET.md).

The first scan searched all production `.rs` files for direct filesystem creation, write, rename, removal, and `OpenOptions` calls, SQLite opens and `execute`/transaction calls, and owner/queue entrypoints. A lexical pass that truncates each file at a trailing `#[cfg(test)] mod tests` found 67 candidate files: 56 in `wavecrate-library`, 6 in `wavecrate-analysis`, 3 in `wavecrate-scan`, 1 in `wavecrate-media`, and 1 in `reson`. This is a class inventory, not a mechanical claim that every matching method name mutates: the scan also finds read-only opens and arbitrary `.execute()` methods. Each row below names the checked path and whether it is an implemented route, a maintenance boundary, or an unresolved legacy exception.
